# Порт для Windows: происхождение

**[Read this in English](PROVENANCE.md)** (основной вариант; этот файл — его русская адаптация).

Этот каталог — порт Lexomorph (ранее SuperDictate Next) для Windows. Это отдельное
приложение, а не вариант сборки macOS-приложения из `swift/`: у них общие файлы
моделей, имена настроек, раскладка файлов данных и поведение, но нет общего исходного кода.

## База импорта

Отправной точкой стал уже существовавший форк для Windows, импортированный целиком:

| | |
| --- | --- |
| Исходный репозиторий | https://github.com/metawka/SuperDictate-win |
| Коммит | `326b1272b14eea390bef7b5c87aafbdd5736b025` |
| Дата | 2026-07-22 |
| Версия при импорте | 2.4.0 |
| Лицензия | MIT (см. `LICENSE`, цепочка авторства в `NOTICE.md`) |

Импорт дословный, без `.git/` и `__pycache__/`. Всё добавленное после этого — работа
этого репозитория, она отражена в его истории.

## Почему импорт, а не подмодуль

Смысл порта в том, чтобы расходиться с форком: у macOS-приложения есть подсистемы,
которых у форка никогда не было (постобработка через LLM, второй движок распознавания,
обучение словаря на SQLite, сегментация по VAD), и чтобы закрыть этот разрыв, нужно
править существующие модули, а не добавлять новые рядом. Подмодуль перенёс бы каждую
такую правку в дерево, которое мы не контролируем, а форк под MIT как раз для этого и
разрешён. `NOTICE.md` сохраняет цепочку авторства целой.

## Связь с `swift/`

Общее по построению, и его сознательно держат синхронным:

- **Файлы моделей.** Те же веса, привязанные к тем же репозиториям и ревизиям и
  проверяемые теми же SHA-256: GGUF-модели LLM как в
  `swift/Sources/Lexomorph/ModelDownload.swift`, модели речи через общий каталог ONNX (ниже).
- **Имена настроек.** Если настройка есть на обеих платформах, у неё один ключ, поэтому
  поведение сопоставимо, а ответы поддержки переносятся.
- **Промпты.** Промпты коррекции и рерайта перенесены дословно из
  `swift/Sources/Lexomorph/LLMPostprocessingPrompts.swift`. Они подбирались опытным путём
  под эти конкретные модели; изменить один на одной платформе без другой значит
  незаметно развести поведение продукта.

Общие также Silero VAD и (экспериментальный, не выпускаемый) хост LLM в `engines\`:
их собирает `tools/build-engines.ps1` (`native/engines/CMakeLists.txt`) из тех же
вендорных копий в `swift/Sources/`, что и macOS-приложение: Silero VAD из whisper.cpp
поверх ggml v0.13.0 и llama.cpp d59d455 с бэкендом CPU (и по желанию Vulkan).
Релизные сборки выполняют коррекцию и рерайт только через OpenAI-совместимый
endpoint. Ранние ревизии подключали llama.cpp / whisper.cpp из апстрима, собранные с
CUDA; эти бинарные файлы никогда не коммитились и не могли быть пересобраны.
Хост распознавания речи — общий исходный код (ниже).

## Распознавание речи: общее, не разошедшееся

Ранние ревизии порта запускали Parakeet TDT v3 через Python-пакет `onnx-asr` или через
Parakeet из дерева whisper.cpp с другим контейнером GGUF, чем в macOS-сборке. Оба пути
удалены. После перехода macOS 0.7.0 на ONNX обе платформы запускают один и тот же
нативный хост `LexomorphOnnxHost` (`native/asr-runtime`, C++ поверх ONNX Runtime
1.23.2) с теми же моделями из одного закреплённого каталога
(`native/asr-runtime/catalog/onnx-models.json`) и той же политикой «только CPU».
Python-часть лишь говорит на кадровом IPC хоста (`superdictate/onnx_host.py`), как это
делает Swift `OnnxAsrEngine`.
